# telemetry-issuers

The telemetry CA of the demonstrator cluster, as cert-manager resources, installed by
`scripts/install-zone/install.sh` as the release `telemetry-issuers` of the demonstrator role, into
the backends' namespace (`observabilityBackends.namespace`, `ztd-observability`). It needs
cert-manager on the cluster: the demonstrator cluster runs its own; on kind,
`scripts/dev/kind-cert-manager-up.sh` installs the pinned version.

| Resource | Issued by | Used by |
|---|---|---|
| `ztd-telemetry-root` (Certificate, Issuer) | self-signed | the zones verify the entry's server certificate against it |
| `otel-entry-server` | the root | the receiving collector's listeners (TLS 1.3 minimum) |
| `ztd-telemetry-<zone>-ca` (Certificate, Issuer) | the root | the entry's listener of that zone trusts it alone (`client_ca_file`) |
| `ztd-telemetry-client-<zone>` | the zone's intermediate | the zone's collectors; copied into the zone by the step `telemetry-client-certs` |

Because each listener trusts one intermediate, the zone of a connection is fixed by which CA could
complete the handshake, not by anything the client sends; the listener's pipeline then overwrites the
`zone` attribute (design of the observability stack, ADR-0012).

## Values

| Key | Default | Meaning |
|---|---|---|
| `zones` | `[]` | `{name, port}` per participant zone, filled by the installer from `observabilityBackends.entry.zones`; at least one |
| `serverName` | `otel-entry.ztd-observability.svc` | the DNS name in the server certificate, verified by every collector |
| `durations.*` | 10 y root, 5 y intermediate, 1 y server and client | certificate lifetimes; cert-manager renews at two thirds |
| `privateKey` | ECDSA P-256 | the key type of every certificate |

No private key is rendered by this chart; each one is generated by cert-manager into a Secret of
the namespace.
