# Evidence — CMC attested-TLS channel binding

Evidence that the CMC attested-TLS library is pinned, wrapped behind the `internal/atls`
package, and that its channel binding holds end to end on the target cluster.

Every artefact here is regenerated by a script; nothing in this folder is edited by hand except
this file. The three channel proofs are written by `scripts/atls-probe/prove-mutual-handshake.sh`, `prove-tampered-binding.sh` and
`prove-session-loss.sh` (described in `scripts/README.md`), the wrapper isolation by the script in its folder.
Private keys never land here — only records, logs and verdicts. In the logs the scripts' temporary
directory appears as `<work>` and the host name as `<host>`.

## Scope

| Pinned library | `github.com/Fraunhofer-AISEC/cmc` **v0.9.15** (commit `6754d3c`) |
|---|---|
| Wrapper | `internal/atls` — the only package allowed to import CMC |
| Attestation model | one `cmcd` per zone, reached over gRPC; `libapi` (in-process CMC) for tests only |
| Evidence | CMC software driver (`sw`) — mock evidence, no TEE hardware |
| Binding | RFC 9266 TLS exporter (`EXPORTER-Channel-Binding`), report nonce = `sha256(exporter ‖ prover leaf cert)` |

## Layout

| Folder | Proves | Contents |
|---|---|---|
| `mutual-handshake/` | Two processes complete a mutually attested handshake and derive identical binding material | `server.json` and `client.json` — the record of each end: binding, peer fingerprint, verdict, `ValidUntil` — and the logs of both ends and of both `cmcd` |
| `tampered-binding/` | A tampered binding aborts the handshake | `relay.json` (the man-in-the-middle: its two TLS sessions and their different bindings), `server.json` and `client.json` with the refusal each end returns, logs, and `control-other-identity/` (a relay without the peers' identities is stopped by the identity check) |
| `session-loss/` | Killing either side mid-session produces recorded re-establishment behaviour and error surfaces | `reconnect-findings.md` (per scenario: surviving end, error, sentinel or transport, time to detect, reconnect outcome), `findings.json`, and one folder of records and logs per scenario |
| `wrapper-isolation/` | No package outside the wrapper imports CMC types; the interface is frozen | `depguard` run output, wrapper test run, and `api-freeze.txt`: the frozen commit, the listing of the exported API as frozen, and the run of the test that guards it |

Every folder of the three channel proofs also holds `environment.json` — the commit, the Go and CMC
versions, the date and the kind of host (`local`, `ci` or `target-cluster`) of the run that
produced it — `verdict.txt` with every check the script made, the configuration each `cmcd` ran
with, and `cmcd-check.log`: each `cmcd` produces reports with metadata, and both verify them.

To check a folder again without running anything: `scripts/atls-probe/prove-mutual-handshake.sh --verify
docs/evidences/cmc-atls-channel-binding/mutual-handshake` (likewise for the other two).

The pin itself is recorded in [ADR-0010](../../adr/0010-session-attestation-through-cmcd.md).

## Status

Local runs (two `cmcd` and the probe processes on one machine) and target-cluster runs are kept
apart. The evidence committed here comes from a local run. CI re-runs the same scripts on every
pull request that touches the channel, the probe or the scripts, so reviewers can verify that the
proofs reproduce; it uploads its own records as an artefact and never writes this folder. Only a
target-cluster run closes a proof.

| Proof | Evidence here | From | Target-cluster run |
|---|---|---|---|
| Mutual handshake, identical binding | `mutual-handshake/`: both ends established with verdict `success` and hold the same 32-byte binding | local run | pending |
| Tampered binding aborts | `tampered-binding/`: through a relay holding certificates with the peers' identities, both ends refuse with `ErrBindingMismatch`; no application data crosses | local run | pending |
| Session loss recorded | `session-loss/reconnect-findings.md`: server killed, client killed, `cmcd` killed with a channel open and during a handshake (either zone), server frozen; one reconnect attempt each. Run on the v1 interface: a peer whose `cmcd` is down is recorded as `ErrPeerAborted` | local run | pending |
| Wrapper isolation, interface frozen | `wrapper-isolation/prove-isolation.sh` regenerates `depguard-run.txt` (clean tree passes; throwaway CMC and `atlstest` imports outside `internal/atls` fail and are named), `atls-test-run.txt` (wrapper tests, plain and under `-race`) and `api-freeze.txt` (the frozen commit, the listing of the exported API, and the guard test: it passes on the clean tree, and fails and names throwaway exported identifiers). **The interface is frozen at v1 on our side**; the contract is [Attested channel control](../../attested-channel.md), which states what v1 decided for each error surface the session-loss proof revealed. The partner sign-off under the interface-freeze process is pending | local run | not applicable: proven in the repository |

The same scripts produce the target-cluster evidence: run them where the zones' `cmcd` and the
probe can reach each other, with `ATLS_HOST_KIND=target-cluster`.
