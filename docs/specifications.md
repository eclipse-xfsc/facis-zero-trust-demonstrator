# Changes and additions to source specifications

Where the implementation departs from, or adds to, the Software Requirements Specification and the
Technical Development Requirements — and why.

Each entry records the specification clause, what changed, the reason, and the decision record that
governs it. Architecture decisions themselves live in [`adr/`](adr/index.md); this page is the index
from specification clause to decision, so a reviewer can start from the requirement rather than from
the decision.

| ZT-27 and the observability stack's buffering — "drop the oldest data" when a collector's bound is reached | The collectors buffer while the export path is down, in a bounded queue (file-backed on the node collectors). Nothing in the zone waits on it | The upstream collector's sending queue has no drop-oldest mode; the retry window ages the oldest batches out, and the newest are refused only once the queue is full | [ADR-0012](adr/0012-central-observability-backends.md) · declared here |
| TDR, QA requirements, ORCE Automation QA — "Deploy, redeploy and uninstall must run with zero manual intervention" | Deploy, redeploy and uninstall of a zone run without a manual step (`scripts/install-zone/install.sh`, or the ORCE lifecycle workflow). OpenBao's bootstrap Job unseals the server on install and on every upgrade that changes a value, which may restart it. A restart the lifecycle does not cause (an eviction, a node reboot, an out-of-memory kill) leaves the server sealed and not ready until `scripts/secrets/unseal.sh` is run, a documented manual step | The unseal key lives in a Kubernetes Secret the bootstrap owns; an automatic unseal needs a key-management backend (a cloud KMS, an HSM or another OpenBao) that the demonstrator does not operate. ## Deviation status

Every reading above is declared rather than assumed. The five governing ADRs of 2026-09-08 (0001 to
0005) were submitted to FACIS as the F-05 deviation package and the OpenBao licence exception as F-07;
both are open at the time of writing. ADR-0009, which supersedes 0001 through the fallback clause that
record foresaw, entered as *Proposed* after the package was submitted and is carried into its next
update. A reading found after that package was submitted is recorded here as soon as it is found and
carried into the next update of the package. A reading that FACIS declines is handled as a plan change
under the written-agreement rule, not absorbed into the implementation.

Eight readings postdate that package and are not yet part of a submitted one: the CI workflow reading,
added when the first Go module arrived; the reuse of the attestation component's own report format for
the mock attestation; the channel binding the report actually carries; the placement of the
expected launch digest in the trust list; the manual unseal of OpenBao after a restart outside
the lifecycle, read against the "zero manual intervention" rule; the contingency transport of the
observability export until the CUG; the log store still open against ZT-27's logs criterion; and the
collectors' buffer, which refuses new data rather than dropping the oldest when it is full. They are declared here so that they are not mistaken for
omissions.
